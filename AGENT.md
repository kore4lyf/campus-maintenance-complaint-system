# Project Entry Point

Entry file for AI coding agents working on this project. Built per the
Idea-to-Product six-file context convention. The pre-existing `AGENTS.md`
(Next.js 16 agent rules, auto-generated by `create-next-app`) and `CLAUDE.md`
(auto-gen pointer to `AGENTS.md`) are left untouched — they serve Next.js-tooling
purposes, not the build context.

## Application Building Context

This project uses the Idea-to-Product six-file context system. Before writing any
code, read these files in order:

1. `@./context/project-overview.md` — what we are building, who it is for, scope, success criteria
2. `@./context/architecture.md` — stack, folder boundaries, data model, auth, invariants
3. `@./context/code-standards.md` — language, framework, styling, API rules, file organization
4. `@./context/ui-context.md` — design tokens, components, layout patterns
5. `@./context/ai-workflow-rules.md` — how the build is sequenced, protected files, what to update as you go
6. `@./context/progress-tracker.md` — current phase, what is done, what is next, open questions

Every AI coding session on this project starts by reading these files in this
order. They are the system of record. If implementation uncovers a decision no
file records, stop and update the relevant file before writing code.

## Project Conventions

- Build feature by feature.
- One unit at a time. See `@./context/ai-workflow-rules.md` for the gating
  checklist before moving on.
- Update `@./context/progress-tracker.md` after every meaningful implementation
  change.
- Cross-reference decisions to the academic doc
  (`Campus Maintenance Complaint Management System.md`) and the Developer Brief
  (`Developer Brief — AI Triage + Vercel AI SDK Migration.md`) before introducing
  new tooling or schemas.
