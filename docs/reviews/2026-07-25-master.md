## Summary

This change delivers the full project foundation: TypeScript strict mode, 8 Mongoose schemas, index creation, Jest + React Testing Library, and a passing build/dev server. The structural quality is solid, but it contains one critical correctness bug (a TTL index that will auto-delete complaints at SLA breach time, with dev/prod inconsistency) and fails its own lint gate. The model tests also don't actually test the production schemas they're meant to protect.

## Blockers
### 🔴 TTL index deletes complaints at SLA breach, `lib/db/models/complaint.ts:73`
**Problem**: `complaintSchema.index({ slaResolveBy: 1 }, { expireAfterSeconds: 0 })` creates a MongoDB TTL index that deletes documents the moment `slaResolveBy <= now()`. Complaints vanish exactly when they breach SLA, destroying the records needed for escalation, technician assignment audit, and reporting.
**Why it matters**: Production data loss. The SLA engine, admin queue, and reporting slices all depend on past-due complaints remaining queryable. Worse, `indexes.ts` re-creates this field without `expireAfterSeconds`, so dev (autoIndex=true) auto-deletes while production (autoIndex=false) does not — the same code behaves differently per environment.
**Suggested fix**: Remove the `expireAfterSeconds: 0` index from the schema. If retention-after-closure is desired, use a separate `archivedAt` field with a real retention TTL. Keep only the manual index definitions in `lib/db/indexes.ts` and remove inline `.index()` calls from the schema.

## Major
### 🟠 Lint fails — 21 errors, AC-8 is not met, `lib/db/models/*.test.ts`, `connection.test.ts`, `layout.test.ts`
**Problem**: Every test file uses `require("mongoose")` / `require("./connection")`, violating the project's `@typescript-eslint/no-require-imports` rule. `npm run lint` exits non-zero.
**Why it matters**: The spec requires `npm run lint` to pass without errors. A CI/lint-gated merge would block this PR, and the underlying tests are written in a style the project explicitly forbids.
**Suggested fix**: Rewrite tests to use `jest.mock` at the top of each file with ES module `import` syntax, or add a per-file `/* eslint-disable */` block with a documented reason. Do not weaken the global rule.

### 🟠 Model tests do not test the actual schemas, `lib/db/models/*.test.ts`
**Problem**: Each model test redefines the schema inline with `new mongoose.Schema({...})` instead of importing the production schema/model from `lib/db/models/*.ts`. They only assert that the inline schema has the expected fields.
**Why it matters**: If someone changes a field type, removes a required validator, or alters an enum in `lib/db/models/complaint.ts`, the tests will still pass because they test a copy. This defeats the purpose of schema-level tests.
**Suggested fix**: Import the actual schema (`import { complaintSchema } from "./complaint"`) or the compiled model and assert on real behavior (validator rejection of bad enums, required-field errors, defaults).

### 🟠 Indexes duplicated between schemas and `lib/db/indexes.ts`, `lib/db/models/complaint.ts:73-77`, `indexes.ts:6-23`
**Problem**: The complaint schema defines five single-field indexes inline; `indexes.ts` redefines them manually. The architecture rule is "Index creation in `/lib/db/indexes.ts`; the connect hook calls it once on first connect." The duplicate on `slaResolveBy` is the direct cause of the blocker above.
**Why it matters**: Violates the architecture invariant, wastes index build time on every connection, and creates dev/prod behavioral divergence because Mongoose `autoIndex` (on in dev) and the manual `createIndexes` call race/overlap.
**Suggested fix**: Remove all inline `.index()` calls from schemas. Keep index definitions only in `lib/db/indexes.ts`.

## Minor
### 🟡 Mongoose version drifts from architecture spec, `package.json:32`
**Problem**: `"mongoose": "^9.8.0"` is installed, but `architecture.md` specifies Mongoose 8.x. The spec was not updated to justify the upgrade.
**Why it matters**: A major-version bump without documented sign-off risks silent API/behavior changes (e.g., `lean()`, `session()` handling, internal driver version).
**Suggested fix**: Either downgrade to `8.x` or record the version bump in `architecture.md` and `progress-tracker.md` with rationale.

### 🟡 Root layout test triggers invalid DOM nesting warning, `app/layout.test.tsx:6`
**Problem**: `render(<RootLayout>...</RootLayout>)` wraps the component in a `<div>`, but `RootLayout` returns `<html>` + `<body>`. React warns: "In HTML, `<html>` cannot be a child of `<div>`."
**Why it matters**: Tests pass, but the warning indicates the test harness is set up incorrectly for a Next.js root layout. Future layout changes could mask real hydration issues.
**Suggested fix**: Use `render(..., { container: document.documentElement })` or test metadata/layout attributes via shallow assertions rather than full DOM render.
